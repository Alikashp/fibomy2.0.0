## 2. Стресс-галерея макетов (`tests/gallery/`, ТЗ 7.3)

**Что:** каждый вариант × каждая тема × 3 фикстуры контента → PPTX → проверки → PDF → PNG.

| Фикстура | Содержание |
|---|---|
| `min` | минимум элементов из `applies_when`, короткие тексты, короткие числа |
| `typical` | среднее число элементов, тексты ~70% вместимости, русский |
| `max` | максимум элементов, тексты ровно на базовой вместимости, **длинные слова** — казахский и немецкий («Qualitätssicherungsmaßnahmen»), самые длинные значения из `applies_when` |

Для `chart_*` — синтетические datasets: 2 и 12 категорий, 1 и 3 серии, отрицательные значения, доли на сумму 97 и 103%.

**Проверки на каждом слайде** (из `core/checks`, ТЗ 7.1): элементы в границах слайда и в полях; нет пересечений, кроме разрешённых макетом; текст влезает по метрикам fitter'а без обрезки на фикстурах `min` и `typical` (на `max` допустим шаг кегля, но не обрезка); шрифт и кегль из темы; цвета из палитры темы; заполненность полезной зоны 40–75%; доля цвета темы на слайде не ниже порога `05_LAYOUTS.md`, 8 (титул и финал ≥ 35%, контентные ≥ 6%, с диаграммой ≥ 10%); у диаграммы есть подписи значений и ось с единицей.

**Где и когда:** job `gallery` в workflow «tests» на каждый PR (без ключей). Вывод — артефакт `gallery-pdf` (одна PDF-книга: вариант × тема × фикстура, 22 × 4 × 3 = 264 слайда) и PNG-миниатюры для ревью. Новый вариант или тема не мёржится без зелёной галереи.

**Время:** 264 слайда → 12 PPTX по теме и типу фикстуры, конвертация ~2–3 с на файл → ~1,5 минуты.

### 3.2 Что проверяется

`check_case.py` переходит с JSON старого движка на `DeckSpec` + PPTX:
- **обязательные проверки кейсов** из ТЗ 7.4 («обязано быть» / «не должно быть») — по тексту слайдов `DeckSpec`, как сейчас;
- **новые для DeckSpec:**
  - пара «число + ячейка»: у каждого числа есть `source_ref`, значение совпадает с ячейкой (ТЗ 4.8.2);
  - G-04: слайд `role = ask` есть, он последний перед `closing`, в нём «4,5 млн»; `chart_share` с 46/27/18/9 — один; `chart_series` с январём–июнем — один, все 6 точек; 2 400 и 8 000 с подписями;
  - G-05: `slides[0].title == topic` после нормализации пробелов и кавычек;
  - «по теме»: ни одного `chart_*`; у слайдов с числами `footnote` = «Оценочные данные — проверьте перед показом»;
- **новые для PPTX** (читаем готовый файл):
  - файл открывается python-pptx, конвертируется LibreOffice;
  - 0 слайдов, где единственный объект — картинка;
  - диаграммы нативные (`GraphicFrame` с `chart`), данные диаграммы = `DeckSpec.data` = ячейки dataset;
  - все шрифты — Arial; автоподбор выключен; нет элементов за границами;
  - детерминированные проверки ТЗ 7.1 — 0 ошибок;
- **метрики колоды:** время по этапам, стоимость, число деградаций и сокращений fitter'а, метрики разнообразия (`05_LAYOUTS.md`, 4.4).

Отчёт в PR — как сейчас: таблица «кейс × прогон», нарушения, время, стоимость; артефакт `golden-decks` с DeckSpec, PPTX и PDF; текст колод в лог job'а.

### 3.3 Базовая линия

### 3.4 Как устроен golden с сессии 2

- `tests/golden/run_golden.py` вызывает `core.pipeline.generate_deck`: G-01 ×2, G-02 ×2, G-03, G-04 ×3, G-05 — новый движок; питч-дек — старый движок до сессии 3 (D-038). В артефакте — DeckSpec, PPTX и PDF каждого прогона.
- `check_case.py` читает DeckSpec (приводит к единицам текста старого формата) и добавляет проверки по структуре: роль `ask` последней, данные диаграмм, роль `definition`, тема на титуле. `run_golden.py` проверяет готовый PPTX: нативные диаграммы с данными DeckSpec, Arial, без автоподбора, PDF собран.
- Ручной запуск workflow с полем `outline_effort` (например, `medium`) — тот же корпус с другим уровнем рассуждений OUTLINE; у каждого уровня свой комментарий в PR (вопрос 13).

## 4. Проверка открытия PPTX

| Уровень | Что | Когда |
|---|---|---|
| Автоматически | python-pptx открывает и читает все объекты; LibreOffice конвертирует без ошибки; XML частей слайдов и диаграмм проходит валидацию по схемам ECMA-376 Transitional (`lxml`; схемы кладутся в `tests/schemas/`, если позволят лицензия и размер — иначе проверка пропускается с предупреждением) | галерея и golden, каждый PR |
| Автоматически | «контрольные признаки восстановления»: порядок элементов `a:tcPr` (фаза 2), уникальность `id` фигур на слайде, связи `rels` на существующие части, типы содержимого в `[Content_Types].xml` | галерея |
| Вручную | владелец открывает 5 колод в PowerPoint 365 (Win или Mac), Keynote, Google Slides: без предложения восстановить, вёрстка как в PDF, диаграмма редактируется, шрифт Arial без замены | конец сессий 1, 3 и 5 (`09_PLAN.md`) |

Чек-лист ручной проверки — по образцу `docs/SPIKE_PPTX.md`, раздел 5, с колодами из артефакта golden.
