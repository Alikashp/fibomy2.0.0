# 08. Переход со старого движка на новый

**Статус:** проект на утверждение · **Дата:** 30.09.2026 · **Опирается на:** `03_ARCHITECTURE.md` (2.1), `04_CONTRACTS.md` (8), `09_PLAN.md`, D-009, D-010, D-026

---

## 1. Принципы

1. **Без флагов** (D-026). Бот переходит на новый движок в первой сессии реализации. Пользователей нет — сравнивать движки на трафике не нужно.
2. **Старый код остаётся в репозитории, пока новый не пройдёт golden**, но бот его не вызывает. Он нужен как эталон для сравнения колод и для быстрого отката.
3. **Миграции БД на время перехода только добавляют.** Ни одна таблица и колонка, которые читает старый код, не удаляется до фазы 2. Поэтому откат кода не требует отката БД.
4. **Воркер выкатывается раньше бота**, когда меняется набор задач очереди.

## 5. Выкатка сессии 1 (переключение)

1. PR сессии 1 смёржен, Railway собирает образ (Wait for CI).
2. **Сначала воркер:** он получает обе задачи (старую и новую) и LibreOffice.
3. **Потом бот:** начинает ставить `generate_deck_job`.
4. Если бот поднялся раньше воркера и успел поставить новую задачу, старый воркер её не знает — ARQ завершит задачу ошибкой «function not found». Колода останется `queued`; сторож нового воркера через 5 минут переведёт её в `failed` и напишет пользователю «Генерация прервалась, нажмите «Повторить»». Пользователей нет, риск — только у тестировщика.
5. Проверки после деплоя — в описании PR сессии 1 (сценарий «тема → PPTX + PDF»).

## 6. Откат

| Ситуация | Как откатить | Что с данными |
|---|---|---|
| После сессий 1–4 новый движок ломает генерацию | **Railway → Deployments → предыдущий деплой → Rollback** для воркера и бота (минуты). Затем revert PR в GitHub, чтобы следующий деплой не вернул поломку | `decks` остаются, старый код их не читает. Задачи `generate_deck_job` в очереди на старом воркере упадут — пользователь их не дождётся (пользователей нет) |
| После сессии 5 (старый код удалён) | revert PR сессии 5: возвращает старые файлы, Playwright и базовый образ. Образ собирается заново (~10 минут) | без изменений |
| Сломалась миграция `0005` на старте | Railway Rollback: `0005` не применилась целиком (транзакция), старый код стартует | — |
| Новый движок работает, но плохо на части входов | не откатываем: чиним в той же ветке сессии, golden покажет регрессию | — |

Переменные окружения: новые переменные нового движка имеют значения по умолчанию, старый код их игнорирует — при откате менять ничего не нужно.

- Шаг 3: образ собирается без Playwright; размер образа меньше прежнего; генерация всех видов входа.
- Шаг 4: бот и воркер стартуют после `0006`, в логах нет обращений к `presentations`.
