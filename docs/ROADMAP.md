## Дальше — по порядку

1. **Адаптер RabbitMQ для основного Фибоначчи.** Основной бот ставит задачу в свою очередь RabbitMQ, мы собираем колоду и отдаём результат. Ждём ответов разработчиков основного бота:
   - `chat_id` пользователя — передаётся в задаче или файлы отдаём им;
   - токен бота — отправляем файлы в Telegram сами от имени основного бота или нет;
   - статус в их БД — кто и как его обновляет;
   - очередь старого генератора — имя, формат сообщения, кто слушает сейчас;
   - число слайдов — как задаётся у них;
   - шаблоны — какие у них есть и как сопоставить с нашими темами.
2. **Пакет «сессия 2» — качество колод:**
   - конкретика в докладах по теме (меньше общих слов);
   - страховка кодом для целей и рядов чисел;
   - потери при сжатии длинных документов;
   - слайд-запрос;
   - оформление: цитаты, плюсы / минусы, уровни, контакты на финале.
3. **Стоимость длинных документов:** в CONTENT — только нужные слайду фрагменты, а не весь `SourceDigest` (сейчас он целиком в системном промпте каждого вызова — `docs/features/material.md`).
4. **Память на Railway:** Chromium старого движка в воркере, объём Redis (файлы колод API без S3, временные файлы).
5. **Питч-дек на новом движке и удаление старого движка.** Сюжет питч-дека на kinds нового движка, бриф с файлами через INGEST; в API `presentation_type = "pitch_deck"` начинает работать без смены контракта. Затем одним PR удаляются: `src/generation/` (кроме временного хранилища `src/generation/uploads.py` — переезжает в `core/storage`), `src/schemas/`, `src/templates/`, `src/layouts/zones.py`, задача `generate_presentation_job`, маршрутизация `dialog.engine_for`, старые промпты в `prompts/` (кроме `prompts/models.yaml`), `docs/PROMPT_REVIEW.md`, тесты старого движка; базовый образ — без Playwright и Chromium. Таблица `presentations` остаётся: удаляющая миграция — только отдельным решением владельца.
6. **S3 для API:** файлы колод API на 24 ч вместо 1 ч в Redis (код готов, `core/storage/files.py`; нужен бакет и переменные `S3_*` у воркера и api).
7. **Исследование: режим поиска фактов в интернете** для докладов по теме — источники, стоимость, как не выдумывать числа.

## Найдено, в очередь не поставлено — решает владелец

- **Откат кода через миграцию роняет старт сервисов:** `alembic upgrade head` в `db/session.py` падает на ревизии из базы, которой нет в старом коде (`Can't locate revision`, проверено 06.11.2026). Исправление — небольшое: при неизвестной ревизии в базе стартовать с предупреждением, а не падать. Как откатываться до исправления — `README.md`, «Откат».
- **План организации кода** (сессия 7, `docs/PROGRESS.md`): после удаления старого движка — имена и раскладка (`main.py` → `bot/`, `worker.py` → `worker/`), `generate_deck` оглавлением, сценарии в `app/`, правила импортов в CI.
