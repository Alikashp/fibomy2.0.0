# Фичи

Что делает каждый кусок продукта, как он работает и где в коде — **как есть сейчас** (D-080). Перед правкой фичи прочитайте её файл; общая картина — `README.md` в корне.

## Шаблон файла

| Раздел | Что в нём |
|---|---|
| **Назначение** | Одна-две строки: зачем фича нужна |
| **Как работает** | Поток: что делает пользователь или клиент → что делает код → побочные эффекты |
| **Где в коде** | Файлы и функции; настройки и конфиги |
| **Нюансы** | Правила и подводные камни, на которые легко наступить при правке. Правило должно читаться без чтения кода |
| **Что не разобрано** | Необязательный: что в описании не подтверждено кодом или не сверено построчно. Нечего — нет раздела |

## Правила

- **Код — источник истины.** Описание разошлось с кодом — правится описание, в той же задаче.
- **Файл фичи обновляется вместе с кодом фичи.** Новая фича — новый файл и строка в таблице ниже.
- **Без перечислений, которые есть в источнике.** Число вариантов, список тем, все переменные окружения — в `layouts/`, `themes/`, `.env.example`; здесь — ссылка и правило.
- **Пути проверяет CI** (`scripts/check_docs.py`): каждый путь в файлах фич существует, каждый файл есть в таблице ниже.
- Контракт REST API для внешнего клиента — `docs/API.md`; здесь — как API устроен внутри.
