# План и выбор вариантов

**Назначение:** решить, из каких слайдов состоит колода и как выглядит каждый. План пишет модель (OUTLINE), вид слайда выбирает код (SELECT).

## Как работает

1. **OUTLINE** — один вызов LLM (`core.planning.outline.plan_deck`). Модель возвращает:
   - анализ источника: жанр, тезисы со статусом (факт, план, требование…), запросы;
   - план содержательных слайдов: kind, роль, заголовок-утверждение, ключевая мысль, ссылки на фрагменты, набор данных, запрос картинки;
   - `deck.title_topic` (тема без пожеланий), `deck.user_wishes`, подзаголовок, запрос картинки титула.

   Сюжет задаёт storyline по жанру (`prompts/v2/outline/storylines/`), допустимые kinds — `prompts/v2/outline/kinds.yaml`, число слайдов — `DeckRequest.total_slides` минус титул и финал.
2. **Проверка плана кодом** (три уровня, описание — в начале `core/planning/outline.py`):
   - ошибки (мало слайдов, дубли, пустые поля) — повтор с перечнем ошибок;
   - замечания по разнообразию (bullets не больше 40% слайдов, два одинаковых kind подряд, statement не больше трети, диаграмма без годных данных) — повтор, на последней попытке план принимается с записью в `degradations`;
   - исправления без повтора: лишние слайды отрезаются, «по теме» диаграммы → bullets, слайд-запрос — последним.
3. **Титул** (`core.planning.title.deck_title`): тема без пожеланий с исправленным регистром («ит» → «ИТ»). Слово из `title_topic` принимается, только если оно есть в теме пользователя (с допуском на опечатку) и в той же письменности (D-076).
4. **Данные диаграмм** (`core.planning.datasets`): модель указывает только набор, колонку подписей, 1–3 колонки значений и строки; числа в диаграмму ставит код (D-028).
5. **Картинки** (`core.pipeline.plan_images`): какие слайды получат ИИ-картинку — титул и слайды с `image_query`, не подряд (`images.md`).
6. **SELECT** (`core.selection.select.select_deck`) — вариант макета на каждый слайд, без LLM:
   - фильтр применимости по `applies_when` варианта (число элементов, картинка, длина заголовка по метрикам шрифта);
   - скоринг: штраф за повтор варианта и за ту же визуальную семью у соседа, бонус за совпадение роли, небольшой шум от `seed`;
   - нет применимых — запасной вариант kind, затем bullets.

   У comparison вариант уточняется после CONTENT по полярности («за / против», «было / стало») — `reselect_comparison`.

## Где в коде

- `src/core/planning/outline.py` — вызов, проверки, исправления; `src/core/planning/title.py`; `src/core/planning/datasets.py`.
- `src/core/selection/select.py` — фильтр, скоринг, `without_image` (вариант без картинки, если она не пришла).
- `src/core/models/outline.py` — схема ответа OUTLINE, роли и жанры; `src/core/models/layout.py` — `LayoutSpec`, `capacity`.
- Промпты — `prompts/v2/outline/`; модель и уровень рассуждений этапа — `LLM_MODEL_OUTLINE`, `LLM_EFFORT_OUTLINE`.

## Нюансы

- **OUTLINE — 2 попытки** (`OUTLINE_ATTEMPTS`). Не получилось — `DeckError("OUTLINE_FAILED")`, колода не собирается: без плана деградировать некуда.
- **«По теме» диаграмм нет:** чисел из источника нет, а выдумывать их модели нельзя. Слайды с числами «по теме» получают сноску-оценку (`content.md`).
- **Жанр «по теме» всегда `topic`:** если модель вернула другой, код его заменяет и пишет деградацию `genre:…->topic`.
- **Выбор детерминирован по `seed`:** тот же `seed` и тот же план — та же раскладка. `seed` пишется в `DeckSpec.meta.seed`; не задан в запросе — случайный.
- **Цветные варианты** (пауза, полоса, картинка на цветном фоне) — не ближе трёх слайдов к титулу, финалу и друг к другу (D-066).
- **Вариант с картинкой** выбирается, только если слайду выделена картинка; если она не успела, слайд переключается на вариант без картинки того же kind — содержание от этого не меняется (D-031).
