# Текст слайдов

**Назначение:** написать содержание каждого слайда по плану и вычистить то, что модель испортила: мусорные знаки, обрывки, английские вставки, числа не из источника.

## Как работает

1. **CONTENT** (`core.content.fill.fill_slide`) — по одному вызову LLM на слайд, параллельно (не больше `CONTENT_CONCURRENCY` на колоду). Схема ответа собирается под kind слайда; вместимость выбранного варианта передаётся в тексте задания, а не в схеме.
2. **Длину проверяет код.** Поле длиннее жёсткого предела (вместимость на минимальном кегле) — повтор с просьбой сократить до N знаков. На последней попытке ответ принимается как есть, вписать его без обрезки — задача FIT (`fitting.md`).
3. **Запасной слайд.** Нет валидного ответа за 2 попытки (`CONTENT_ATTEMPTS`) или не успел к дедлайну этапа — слайд-утверждение из плана без LLM: заголовок и ключевая мысль.
4. **Проверка текста** (`core.checks.text`, D-074):
   - склейки названий («BostonScientific» при «Boston Scientific» в источнике) — исправляет код;
   - знаки чужой письменности, «�», слова из двух алфавитов, английские слова строчными в русском тексте — одна перегенерация слайда с перечнем ошибок (`prompts/v2/fit/fix_text.txt`); не помогло — фрагмент вычищается;
   - заголовки (их пишет OUTLINE) — сразу вычисткой.
5. **Проверка чисел** — только «по материалу» (`core.checks.facts`). Каждое число на слайде должно найтись в источнике: в тексте фрагментов или в ячейках. Ошибка — одна перегенерация (`prompts/v2/fit/fix_facts.txt`); не помогло — число убирается, а metrics, оставшийся без чисел, становится утверждением.
6. **Типографика** (`core.text.typography`, D-071): диапазоны, единицы, проценты и разряды неразрывны («60–90 секунд», «92–98 %», «1 250 000»); в ru, kk, uz — десятичная запятая.
7. **Сноска «оценка»** — «по теме» у каждого слайда с цифрами (ТЗ 3.3.3). «По материалу» сноски нет.
8. **Слишком много пунктов** для варианта — другой вариант или два слайда (`core.fitting.resolve.regroup`); пункты не теряются.

## Где в коде

- `src/core/content/fill.py` — системный промпт колоды, схема по kind, вызов, повторы, запасной слайд.
- `src/core/checks/text.py` — мусор генерации; `src/core/checks/facts.py` — числа по источнику.
- `src/core/text/typography.py` — неразрывность и формат чисел.
- Порядок проверок — `src/core/pipeline.py` (`_check_text`, `_check_facts`).
- Промпты — `prompts/v2/content/` (задание по kind — `prompts/v2/content/kinds/`); модель и уровень рассуждений этапа — `LLM_MODEL_CONTENT`, `LLM_EFFORT_CONTENT`.

## Нюансы

- **В схемах ответа нет `maxLength` и `maxItems`** (D-071). Со strict-схемой провайдер обрывает строку на пределе посреди слова — так появлялись «интегра…» и иероглифы в конце строки. Не возвращайте пределы в схему.
- **Системный промпт одинаков байт в байт у всех вызовов колоды** (правила → язык → безопасность → данные → источник → план): его кэширует провайдер, это снижает цену. Всё, что относится к одному слайду, — только в сообщении user.
- **Числа диаграмм модель не пишет** — их ставит код из таблицы (`planning.md`), поэтому проверка чисел их не трогает. Маленькие целые без процента (0–12: «3 шага») тоже не проверяются: в источнике их часто пишут словами.
- **Что считается «мусором»**, определяет `core/checks/text.py`: латиница в именах продуктов (с заглавной, капсом, из источника) и знак «_» — не мусор.
- **Дедлайн:** CONTENT получает время до общего дедлайна колоды (`DECK_DEADLINE_SECONDS`) минус резерв на рендер и конвертацию (`RESERVE_SECONDS` в `src/core/pipeline.py`). Перегенерации из проверок запускаются, только если до дедлайна осталось больше резерва плюс 10 с.
