# Тесты и проверки качества

**Назначение:** проверять код и качество колод до мёржа. Единственный источник о тестах, CI и проверках (D-083): юнит-тесты — без сети и ключей; стресс-галерея — все макеты во всех темах без LLM; golden — реальные генерации корпуса кейсов настоящей моделью; ручная проверка открытия PPTX — владельцем.

## Как работает

### CI

| Workflow | Когда | Что делает |
|---|---|---|
| `tests` | каждый PR | Юнит-тесты, отдельный шаг «API-тесты (контракт второго бота)», снимок собранных промптов относительно базы, `check_case.py` на колодах старого движка; job `gallery` — стресс-галерея и артефакт `gallery-pdf` |
| `golden` | PR, меняющий промпты, ядро, API, воркер, макеты или темы (пути — `on.pull_request.paths` в `.github/workflows/golden.yml`); вручную | Реальные генерации корпуса и одна колода через REST API end-to-end; комментарий с таблицей в PR, артефакт `golden-decks` |
| `siliconflow-probe` | вручную или при правке зонда | Картинки SiliconFlow: замер надписи провайдера или «до / после» обрезки (`scripts/probe_siliconflow_watermark.py`) |

### Юнит-тесты

`tests/unit/`, unittest, запуск — `README.md`, «Быстрый старт». LLM, Telegram и SiliconFlow подменяются; Postgres — SQLite в памяти; LibreOffice нужен только тестам конвертации. Покрывают каждый этап ядра (разбор файлов и чисел, проверки плана, детерминизм SELECT по `seed`, схемы CONTENT, fitter и невлезание, проверки текста и чисел, рендер и финальную проверку PPTX), клиент LLM (параметры по модели, переход на `json_object`, 429), бота (сводка, доступ, склейка текста), воркер и REST API. Отдельно:
- **контракт API** — `tests/unit/test_api_contract.py` сравнивает схему с `tests/unit/api_contract_v1.json` и падает на несовместимом изменении (`README.md`, «Правила»);
- **документация** — `tests/unit/test_docs.py` (`scripts/check_docs.py`): пути, роуты API, карты документов, индекс решений.

### Golden-корпус

1. **Кейсы** — реальные входы с ожиданиями к колоде (ТЗ 7.4): G-01…G-06 (отчёты по документам, ТЗ хакатона, колоды по теме, текст пилота, тема с пожеланиями, docx хирургии) и питч-дек старым движком. Входные файлы — `tests/fixtures/`, список прогонов — `CASES` в `tests/golden/run_golden.py`.
2. **Прогон** (`tests/golden/run_golden.py`) вызывает `core.pipeline.generate_deck`, как воркер, но без Telegram. Каждая колода проверяется:
   - по ожиданиям кейса (`tests/golden/check_case.py`): обязательные числа с подписями, запрещённые утверждения, тема на титуле, роль слайда-запроса;
   - общими проверками текста: нет «…», обрывов посреди слова, чужих письменностей;
   - по готовому PPTX: диаграммы нативные и совпадают с данными, шрифт Arial, PDF собран, страниц столько же, сколько слайдов.
3. **Плюс одна колода через REST API end-to-end** (`tests/golden/run_api_e2e.py`): настоящие процессы api и воркера, Postgres и Redis.
4. **Отчёт** — комментарий бота в PR:
   - таблица прогонов: нарушения «до → сейчас», время по этапам, стоимость, деградации, жанр;
   - картинки отдельной таблицей: время, стоимость картинок и итог колоды с картинками;
   - в шапке — модель, уровень рассуждений, адрес API (`api_host`), версия промптов.

   Колоды — в артефакте `golden-decks`.

### Стресс-галерея

1. **Все варианты × все темы × 4 заполнения:** `min` (минимум элементов, короткие тексты), `typical` (около 70% вместимости), `max` (максимум элементов, самые длинные слова и заголовки, которые вариант принимает), `real` — тексты реальных колод из `tests/gallery/real_texts.yaml`. Для диаграмм — синтетические наборы: мало и много категорий, отрицательные значения, доли не на 100%. Картинки — заглушки без сети.
2. **Путь как в проде:** типографика → fitter → невлезание (вместо LLM — детерминированное сокращение по словам) → рендер → финальная проверка PPTX → PDF → PNG.
3. **Проверки на каждом слайде** (`tests/gallery/checks.py`, ТЗ 7.1): ошибка финальной проверки вёрстки (вылет, слово шире рамки, наложение, текст за фигурой, «…») — нарушение в любом заполнении; невлезание без resolve — на `min` и `typical`; заполненность зоны контента и доля цвета темы — пороги `FILL_RANGE`, `COLOR_THRESHOLDS`, `DECK_MEDIAN` там же (D-065, D-073; как считается — `docs/design/05_LAYOUTS.md`, 8).
4. **Результат:** `gallery.pdf`, миниатюры тем, `report.md`, `results.json`. В CI — артефакт `gallery-pdf`, по нему владелец утверждает дизайн; из той же галереи собираются превью тем для API.

### Ручная проверка открытия PPTX

Автоматически не проверить, поэтому делает владелец после крупных изменений рендера: колоды из артефакта golden открываются в PowerPoint, Keynote и Google Slides без предложения «восстановить», вёрстка как в PDF, диаграммы и таблицы редактируются, шрифт Arial без замены. Последняя проверка — 06.11.2026, без замечаний (D-001, D-005).

## Где в коде

- `tests/golden/run_golden.py`, `tests/golden/check_case.py`, `tests/golden/run_api_e2e.py`, `tests/golden/prompt_snapshot.py`.
- `tests/golden/baseline.json` — «до» для сравнения нарушений (колоды старого движка).
- `tests/gallery/build_gallery.py`, `tests/gallery/checks.py`, `tests/gallery/fixtures.py`, `tests/gallery/real_texts.yaml`.
- Workflow: `.github/workflows/golden.yml`, job `gallery` в `.github/workflows/tests.yml`.

## Нюансы

- **Golden стоит денег и нужен ключ:** секрет `OPENAI_API_KEY` (картинки — `SILICONFLOW_API_KEY`). Запускается на PR, меняющих промпты, ядро, API, воркер, макеты или темы (пути — в `golden.yml`), и вручную со входом `outline_effort`.
- **Картинки заказывают только G-05 и G-06** (`Case.images`), остальные кейсы и API end-to-end — с `image_mode: none`.
- **Нарушения `check_case` не валят workflow:** golden красный, только если генерация упала. Нарушения читают глазами и сравнивают с прошлыми прогонами — у модели разброс, одно-два нарушения в G-01 и G-04 встречаются в каждом прогоне.
- **Порог сигнала по стоимости** — средняя выше 4 ₽ (D-041); бюджет колоды — 3 ₽.
- **Базовая линия «до»** — `tests/golden/baseline.json` (колоды старого движка). Новый движок не должен давать по кейсу больше нарушений, чем там.
- **Ложные срабатывания `check_case` чинятся в `check_case`**, а не правкой ожиданий кейса под результат: в сессии 5 так сужали регулярки для G-03 «отчётности» и G-05 «по данным».
- **Правка промпта** — новая строка в `prompts/v2/VERSION`; снимок собранных промптов до и после (`prompt_snapshot.py`) workflow «tests» показывает в Summary.
- **Галерея не зовёт LLM** и не нуждается в ключах — её можно собрать локально (`README.md`, «Быстрый старт»). Нарушение финальной проверки в любом заполнении — job `gallery` красный.
