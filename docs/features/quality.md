# Golden и галерея

**Назначение:** проверять качество колод до мёржа. Golden — реальные генерации корпуса кейсов настоящей моделью; галерея — все макеты во всех темах без LLM. Оба запускаются в CI.

## Как работает

### Golden-корпус

1. **Кейсы** — реальные входы с ожиданиями к колоде (ТЗ 7.4): G-01…G-06 (отчёты по документам, ТЗ хакатона, колоды по теме, текст пилота, тема с пожеланиями, docx хирургии) и питч-дек старым движком. Входные файлы — `tests/fixtures/`, список прогонов — `CASES` в `tests/golden/run_golden.py`.
2. **Прогон** (`tests/golden/run_golden.py`) вызывает `core.pipeline.generate_deck`, как воркер, но без Telegram. Каждая колода проверяется:
   - по ожиданиям кейса (`tests/golden/check_case.py`): обязательные числа с подписями, запрещённые утверждения, тема на титуле, роль слайда-запроса;
   - общими проверками текста: нет «…», обрывов посреди слова, чужих письменностей;
   - по готовому PPTX: диаграммы нативные и совпадают с данными, шрифт Arial, PDF собран, страниц столько же, сколько слайдов.
3. **Плюс одна колода через REST API end-to-end** (`tests/golden/run_api_e2e.py`): настоящие процессы api и воркера, Postgres и Redis.
4. **Отчёт** — комментарий бота в PR:
   - таблица прогонов: нарушения «до → сейчас», время по этапам, стоимость, деградации, жанр;
   - картинки отдельной таблицей: время, стоимость картинок и итог колоды с картинками;
   - в шапке — модель, уровень рассуждений, адрес API (`api_host`), версия промптов.

   Колоды — в артефакте `golden-decks`.

### Стресс-галерея

1. **Все варианты × все темы × 4 заполнения:** `min`, `typical`, `max`, `real` — тексты реальных колод с длинными заголовками и диапазонами из `tests/gallery/real_texts.yaml`.
2. **Путь как в проде:** типографика → fitter → невлезание (вместо LLM — детерминированное сокращение по словам) → рендер → финальная проверка PPTX → PDF → PNG.
3. **Результат:** `gallery.pdf`, миниатюры тем, `report.md`, `results.json`. В CI — артефакт `gallery-pdf`, по нему владелец утверждает дизайн; из той же галереи собираются превью тем для API.

## Где в коде

- `tests/golden/run_golden.py`, `tests/golden/check_case.py`, `tests/golden/run_api_e2e.py`, `tests/golden/prompt_snapshot.py`.
- `tests/golden/baseline.json` и `tests/golden/reports/` — «до» (колоды старого движка).
- `tests/gallery/build_gallery.py`, `tests/gallery/checks.py`, `tests/gallery/fixtures.py`, `tests/gallery/real_texts.yaml`.
- Workflow: `.github/workflows/golden.yml`, job `gallery` в `.github/workflows/tests.yml`.

## Нюансы

- **Golden стоит денег и нужен ключ:** секрет `OPENAI_API_KEY` (картинки — `SILICONFLOW_API_KEY`). Запускается на PR, меняющих промпты, ядро, API, воркер, макеты или темы (пути — в `golden.yml`), и вручную со входом `outline_effort`.
- **Картинки заказывают только G-05 и G-06** (`Case.images`), остальные кейсы и API end-to-end — с `image_mode: none`.
- **Нарушения `check_case` не валят workflow:** golden красный, только если генерация упала. Нарушения читают глазами и сравнивают с прошлыми прогонами — у модели разброс, одно-два нарушения в G-01 и G-04 встречаются в каждом прогоне.
- **Порог сигнала по стоимости** — средняя выше 4 ₽ (D-041); бюджет колоды — 3 ₽.
- **Ложные срабатывания `check_case` чинятся в `check_case`**, а не правкой ожиданий кейса под результат: в сессии 5 так сужали регулярки для G-03 «отчётности» и G-05 «по данным».
- **Правка промпта** — новая строка в `prompts/v2/VERSION`; снимок собранных промптов до и после (`prompt_snapshot.py`) workflow «tests» показывает в Summary.
- **Галерея не зовёт LLM** и не нуждается в ключах — её можно собрать локально (`README.md`, «Запуск»). Нарушение финальной проверки в любом заполнении — job `gallery` красный.
