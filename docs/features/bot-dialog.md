# Диалог бота

**Назначение:** короткий диалог в Telegram, после которого пользователь получает PPTX и PDF. Все параметры видны в одной сводке, каждый меняется кнопкой.

## Как работает

1. **Тип:** доклад или питч-дек (`/new`, кнопка меню «🚀 Новая презентация»).
2. **Тема или текст.** Сообщение до 200 знаков — тема. Длиннее — это текст-материал, тема берётся из первой строки (`dialog.topic_from_text`). Telegram режет сообщения длиннее 4096 знаков: части, пришедшие подряд, склеиваются в один текст (`bot/text_join.py`).
3. **Материал** (у доклада): «есть / нет»; текст сообщением или файл. У питч-дека вместо материала — бриф.
4. **Сводка** (`dialog.summary_text`): тип, тема, материал, язык, аудитория, число слайдов, тема оформления, режим материала. Каждый параметр меняется экраном «Сменить…» с возвратом в то же сообщение. По умолчанию подставляется прошлый выбор пользователя из профиля (`users.last_*`, `users.source_mode`).
5. **«Сгенерировать»:**
   - проверка бесплатного лимита (`billing.md`);
   - материал — во временное хранилище (`material.md`);
   - доклад — строка `decks` и задача `generate_deck_job`; питч-дек — задача старого движка `generate_presentation_job`.
6. **Прогресс и выдача** делает воркер. Он правит статусное сообщение по этапам (`bot/delivery.StatusMessage`) и отправляет PPTX и PDF одним альбомом с подписью: название, число слайдов, тема, предупреждения. После выдачи — кнопка «🆕 Новая презентация».

Профиль (кнопка «👤 Профиль»): ФИО и группа — подставляются на титул и финал. Тарифы — «💳 Тарифы» и `/plan`.

## Где в коде

- `src/main.py` — обработчики aiogram (FSM `Gen` и `Profile`), меню, профиль, оплата, `generate_deck` (постановка колоды нового движка).
- `src/dialog.py` — тексты, клавиатуры, значения по умолчанию, `engine_for` (какой движок).
- `src/bot/text_join.py` — склейка частей длинного текста (D-075).
- `src/bot/delivery.py` — статусное сообщение, тексты ошибок по коду, отправка файлов, подпись.
- `src/bot/admin.py` — `/apikey` для владельца (`rest-api.md`).
- Состояние диалога — Redis (FSM aiogram, `REDIS_URL`); профиль и последний выбор — таблица `users` (`src/db/session.py`).

## Нюансы

- **Движок выбирается по типу** (`dialog.engine_for`): доклад — новый движок, питч-дек — старый (HTML → PDF, только PDF) до его перевода (D-038, D-054).
- **Тема на титуле — без пожеланий:** «…в ит-стартапах со статистикой» → «…в ИТ-стартапах» (`planning.md`, D-076).
- **Текст-материал** — от 20 до 100 000 знаков (`dialog.MATERIAL_MAX_CHARS`); ядро берёт первые 40 000 (`material.md`) и предупреждает в подписи.
- **Склейка частей** ждёт 2,5 с после последней части, но только если пришла длинная часть (от 3000 знаков). Короткая тема обрабатывается сразу. Буфер — в памяти процесса бота: ботов на Railway должно быть не больше одного экземпляра.
- **`/apikey` обрабатывается раньше всех обработчиков диалога** (`bot_admin.register` сразу после создания `Dispatcher`), иначе его перехватил бы обработчик текущего состояния. Не владельцу бот отвечает как на незнакомую команду.
- **Файлы отправляет воркер**, а не бот: у воркера свой экземпляр `Bot`. Отправка повторяется до 3 раз (`delivery.SEND_ATTEMPTS`).
- **Лимит списывается после успешной отправки** (`db/session.count_generation`), не при постановке задачи.

## Что не разобрано

- Обработчики профиля, меню и экрана «Назад» сверены выборочно, не построчно.
- В `02_CJM.md` описаны кнопки «🔁 Повторить» и «📤 Отправить ещё раз» — в коде их нет.
- Тема из текста длиннее 100 знаков обрезается с «…» (`dialog.topic_from_text`). Попадает ли «…» на титул, когда OUTLINE не вернул годный `title_topic`, — не проверено (титул без «…» требует D-071).
