# Подгонка текста

**Назначение:** вписать текст в рамки макета так, чтобы он никогда не обрезался, не заканчивался «…», не наезжал на соседний и не оставлял пустой половину слайда.

## Как работает

1. **Шаги кегля** (`core.fitting.fitter.fit_deck`): у каждого текстового слота — базовый стиль, затем шаги вниз до `min_style` из YAML варианта. Строки считаются по метрикам реального шрифта (Liberation Sans = Arial, D-027) с переносом как у LibreOffice. Не влезло и на минимальном кегле — слот попадает в список `Overflow`, текст остаётся как есть.
2. **Невлезание** (`core.fitting.resolve.resolve_deck`, порядок D-071):
   1. более вместительный вариант того же kind — без LLM, содержание хранится по kind (D-031);
   2. сокращение моделью: «сократи до N знаков», N — по метрикам слота (`prompts/v2/fit/shorten.txt`), до `SHORTEN_ROUNDS` раундов; не хватило — вариант без картинки;
   3. два слайда: пункты делятся пополам, у второго в заголовке «(продолжение)»;
   4. необязательное поле (подзаголовок, пояснение, автор, сноска) убирается целиком, обязательное — слайд заменяется утверждением из плана;
   5. не влезло и это — `FitError`, колода не отдаётся (`RENDER_FAILED`).
3. **Высота по содержимому и заполненность** (`core.fitting.fill`, D-073): карточки и панели ужимаются до «текст + поля», блок встаёт по центру зоны контента. Если он занимает меньше 40% зоны (`FILL_MIN`), карточки, колонки и строки растягиваются по высоте до этой границы. Результат — `Slide.fit` (`items_area`, `boxes`), рендерер рисует по нему.
4. **Финальная проверка по готовому PPTX** (`core.checks.layout.check_pptx`, D-072). Проверяется сам файл, который получит пользователь:
   - текст вылез за рамку по высоте, слово шире рамки;
   - наложение двух рамок, текст вне своей фигуры или за слайдом;
   - текст кончается многоточием.

   Ошибка — исправление через тот же `resolve_deck` (до 2 раундов, `LAYOUT_ROUNDS` в `src/core/pipeline.py`), затем перерисовка; не помогло — `RENDER_FAILED`.

## Где в коде

- `src/core/fitting/fitter.py` — шаги кегля, `Overflow`, высота по содержимому.
- `src/core/fitting/resolve.py` — порядок невлезания, `llm_shorten`, `regroup` (лишние пункты), `renumber`.
- `src/core/fitting/fill.py` — заполненность 40%.
- `src/core/fitting/metrics.py` — метрики шрифта из `fonts/`, перенос строк.
- `src/core/checks/layout.py` — финальная проверка PPTX и доля заполненности (`fill_share`) — та же мера у галереи.
- Стили, рамки, `min_style`, `max_lines`, `never_truncate` — в YAML вариантов `layouts/`.

## Нюансы

- **Обрезки нет нигде**, включая заголовки и подзаголовок титула. Если хочется «просто обрезать» — это нарушение D-071, решение — другой вариант, сокращение или второй слайд.
- **Слово шире рамки — тоже невлезание:** перенос посреди слова («Непротиворечивост / ь») вписыванием не считается.
- **Тема на титуле и числа не сокращаются** (`never_truncate`). Для темы выбирается вариант титула с бо́льшим полем, у числа с единицей сокращается единица.
- **У повторяющихся элементов кегль общий** — по самому длинному тексту, чтобы карточки не различались размером шрифта.
- **Значение и единица — одна строка:** «92–98 %», «4,5 млн ₽» (`suffix` в YAML metrics).
- **Метрики должны совпадать с рендером.** Шрифт в PPTX — Arial, в LibreOffice и в fitter — Liberation Sans с той же шириной. Замена шрифта в теме без метрик в `fonts/` сломает подгонку.
- **Галерея проверяет то же самое** на всех вариантах, темах и заполнениях без LLM (`quality.md`): правку fitter'а сначала смотрите в галерее.
