## 2. PPTX: что собрано и что выяснилось

Файл `spikes/out/spike_deck.pptx`: 5 слайдов 16:9 (12 192 000 × 6 858 000 EMU), сетка 1920×1080, 1 единица = 6350 EMU.

| # | kind / вариант | Объекты |
|---|---|---|
| 1 | chart_series / column_chart + вывод | нативная диаграмма (2 серии × 4 квартала, подписи, легенда, ось «млн ₽»), карточка-фигура, текст |
| 2 | table / native_table | нативная таблица 5×4, шапка в цвете темы, выделенная строка, числа по правому краю, только нижние границы |
| 3 | bullets / cards_grid | 3 карточки-фигуры, круги-подложки, иконки PNG, текст |
| 4 | chart_share / donut | нативная кольцевая диаграмма с процентами, крупное число, текст |
| 5 | process / chevrons | 4 шеврона-фигуры с текстом, подписи под ними; заметки докладчика |

Автопроверка при чтении файла обратно (`pptx_report.json`): 0 объектов за границами слайда, 0 текстовых полей с автоподбором размера.

Размер: PPTX 96 КБ, PDF 94 КБ (без фотографий).

### Находки, которые обязательно учесть в рендерере (фаза 1)

1. **Тень у фигур.** `add_shape` пишет `<p:style>` со ссылкой на эффекты темы (`effectRef idx=2`). Итог — тень в LibreOffice, и, скорее всего, разный вид в разных приложениях. **Решение:** удалять `<p:style>`, все цвета задавать явно.
2. **Кольцевая диаграмма без подписей.** python-pptx для doughnut пишет `showVal=0`: нужно явно `data_labels.show_value = True`. У диаграммы с одной серией появляется автозаголовок из имени серии — нужно `has_title = False`.
3. **Нет API** для границ ячеек таблицы и размера «дырки» кольца — пишем XML напрямую. В `a:tcPr` элементы `a:lnL/R/T/B` должны идти **до** заливки ячейки: при неверном порядке PowerPoint обычно предлагает восстановить файл. В спайке порядок соблюдён; проверяется пунктом чек-листа.
4. **Вместимость текста.** На сетке 1920×1080 **1 pt = 2 единицы**, строка ≈ 1,2 × кегль. Двухстрочный заголовок h1 36 pt требует ≥ 173 единиц высоты, строка display 60 pt — ≥ 144. В первой версии спайка бокс «+40%» был ниже этого, и текст наезжал на подпись. Fitter (ТЗ 3.7) должен считать высоту именно так.
5. **Автоподбор выключен** (`MSO_AUTO_SIZE.NONE`), поля текстовых рамок нулевые — геометрия предсказуема.
6. **Метаданные.** `dc:creator` в OOXML — это «Автор», туда пишется пользователь. «Fibonacci AI» записан в `Application` (docProps/app.xml) и `lastModifiedBy`. Формулировку ТЗ 3.8 «creator = Fibonacci AI» предлагаю понимать так.
7. **Язык текста.** Каждому фрагменту текста проставлен `lang` (например, `ru-RU`): от него зависят проверка орфографии и выбор шрифта для письменности в PowerPoint.
8. **Иконки.** PNG 512 px из шрифта Tabler Icons (MIT), который уже вшит в шаблон doklad. Новых ассетов не добавлено. Цвет иконки «запекается» при генерации: при смене темы через бота (ТЗ 3.11) иконку нужно перегенерировать. SVG-вставка возможна в Office 2016+, но в Keynote и Google Slides не гарантирована — для MVP оставляем PNG.
9. **Версия python-pptx.** Для спайка хватило 0.6.23. Переход на 1.0.x не требуется, но и не мешает.

## 3. Шрифты

Файл `spikes/out/fonts_matrix.pptx`: слайды 1–8 — кандидаты Arial, Calibri, Segoe UI, Verdana, Tahoma, Trebuchet MS, Georgia, Times New Roman. На каждом слайде по строке на каждый из 15 языков (ТЗ 11, вопрос 3) и строка символов с валютами СНГ. Слайд 9 — армянский и грузинский в Sylfaen, Arial и Noto Sans Armenian/Georgian.

### 3.1 Серверная сторона (то, что попадёт в PDF)

LibreOffice на сервере не имеет шрифтов Microsoft и подменяет их через fontconfig. Полная таблица — `spikes/out/fonts_coverage.md`, кратко:

| Кандидат | Замена на сервере | Метрики совпадают | Кириллица и латиница (13 языков) | hy, ka | Строка символов: чего нет |
|---|---|---|---|---|---|
| Arial | Liberation Sans | **да** | ✓ (включая Oʻ U+02BB) | нет глифов | ₽ ₸ ₼ ₾ ֏ ₺ |
| Calibri | Carlito | **да** | ✓ | нет глифов | ₽ ₼ ₾ ֏ ₺ (₸ есть) |
| Times New Roman | Liberation Serif | **да** | ✓ | нет глифов | ₽ ₸ ₼ ₾ ֏ ₺ |
| Georgia | Noto Serif | нет (клон — Gelasio, в образ не положен) | ✓ | нет глифов | ֏ ↑ → ≈ ≤ ≥ |
| Segoe UI, Verdana, Tahoma, Trebuchet MS | Noto Sans | **нет** | ✓ | нет глифов | ֏ ↑ → ≈ ≤ ≥ |

Выводы:
- **Tofu в PDF нет** ни на одном языке и ни в одном символе: недостающие глифы LibreOffice берёт из DejaVu и Noto (hy/ka набраны DejaVu Sans, ₽ — Noto Sans). Но это верно, **только если эти шрифты есть в образе воркера**.
- **Метрическая совместимость решает, совпадёт ли PDF с PPTX.** У Verdana, Tahoma, Trebuchet, Segoe UI и Georgia (без Gelasio) на сервере другой шрифт с другой шириной букв. Переносы строк в PDF разойдутся с тем, что пользователь увидит в PowerPoint, и fitter будет мерить не то. Поэтому они в безопасный список не входят.
- **Символы валют.** В серверных клонах Arial нет ₽ ₸ ₼ ₾ ֏ ₺ — в PDF эти символы набираются другим шрифтом, это заметно при внимательном взгляде. В настоящем Arial на Windows ₽ есть. Остальное — пункт чек-листа.
- **Selawik и Gelasio** (клоны Segoe UI и Georgia) скачать из этой среды не удалось: прокси блокирует GitHub raw. Если Georgia нужна для «академической» темы — проверить Gelasio отдельно.

### 3.2 Что нужно положить в образ воркера (фаза 1)

```
apt-get install --no-install-recommends libreoffice-impress \
    fonts-liberation fonts-crosextra-carlito fonts-dejavu-core fonts-noto-core
```
- Одного `libreoffice-core` недостаточно: без `libreoffice-impress` конвертация PPTX падает с «source file could not be loaded». В этой среде пакет добавил около 40 МБ поверх уже стоявшего core. Реальный прирост образа замерить при сборке Docker (базовый образ Playwright; после перехода на новый движок Chromium можно убрать).
- `fonts-noto-core` — около 42 МБ. Если размер образа критичен, можно ограничиться Noto Sans + Noto Sans Armenian + Noto Sans Georgian.
- Те же TTF нужны fitter'у для метрик (ТЗ 3.7, папка `fonts/`): Liberation Sans и Carlito метрически равны Arial и Calibri, поэтому мерить можно ими.
- Каждой конвертации — свой профиль LibreOffice (`-env:UserInstallation=...`), так сделано в спайке. Это нужно для параллельных конвертаций (ТЗ 5).

## 4. Ограничения спайка
- Не проверены фотографии (cover-crop, сжатие, атрибуция) — нет ключа Pexels в среде. Для D-001 не критично: картинка в PPTX — обычный объект.
- Не проверены line-, bar- и stacked-диаграммы. Column и doughnut покрывают оба механизма (оси и доли); остальные проверим стресс-галереей фазы 1.
- Приложения Microsoft, Apple и Google из этой среды недоступны — всё, что касается них, в чек-листе ниже.
