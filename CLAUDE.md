# Fibonacci AI — контекст для Claude Code

## О проекте

Fibonacci AI — Telegram-бот, который по теме, тексту или документу пользователя генерирует готовую презентацию. Пользователь проходит короткий диалог (тип, тема, аудитория, язык, объём, материал), бот ставит задачу в очередь, фоновый воркер строит структуру слайдов через LLM, подбирает картинки, рендерит HTML-шаблон в PDF и отправляет файл обратно в чат.

Сейчас основная аудитория — студенты и преподаватели (доклады, презентации проектов и результатов); стратегически продукт движется к корпоративным пользователям. Платформа — только Telegram, хостинг — Railway. Планируется API для подключения из другого бота.

Ключевая продуктовая задача ближайшего этапа — уйти от одинаковых слайдов: для каждого типа контента (числа, текст, процесс, сравнение и т.д.) — пул из 4–5 вариантов представления плюс цветовые темы, а также выход в двух форматах: PDF и редактируемый PPTX с нативными таблицами и графиками. Подробности — в `docs/PRODUCT.md`, текущее техническое состояние — в `docs/CURRENT_STATE.md`.

## Карта документации

| Файл | Что внутри |
|---|---|
| `docs/PRODUCT.md` | Продуктовые требования от владельца: ЦА, платформа, монетизация, нагрузка, SLA, модели, форматы, ключевая задача. Источник истины по «что строим». |
| `docs/CURRENT_STATE.md` | Снимок кода на дату анализа: стек, инфраструктура, пайплайн генерации, входные данные, производительность, монетизация, качество кода, риски. |
| `docs/PROGRESS.md` | Журнал сессий: что сделано, что не доделано, следующие шаги, открытые вопросы. Новые записи — сверху. |
| `docs/DECISIONS.md` | Журнал архитектурных решений: дата, решение, почему, отвергнутые альтернативы. |
| `docs/TZ.md` | Техническое задание от техлида. **Пока не создан** — появится позже. |
| `prompts/` | Промпты и конфиги LLM. **Пока не создана** — сейчас промпты лежат в `src/generation/llm.py` (см. правило ниже). |

## Правила работы

1. **В начале каждой сессии** прочитай `docs/PROGRESS.md`, `docs/DECISIONS.md` и `docs/TZ.md` (когда появится). Не начинай работу, не зная последней записи в PROGRESS.
2. **В конце каждой сессии** допиши в `docs/PROGRESS.md` запись: дата, что сделано, что не доделано, следующие шаги, открытые вопросы. Затем сделай коммит и открой pull request в `main`.
3. **Каждое архитектурное решение** записывай в `docs/DECISIONS.md`: дата, решение, почему, какие альтернативы отвергнуты.
4. **Промпты и конфиги LLM** хранятся отдельными файлами в `prompts/`, не в коде. Сейчас это правило нарушено (промпты — константы в `src/generation/llm.py`); перенос — открытая задача.
5. **Секреты** — только в переменных окружения. Никогда не в коде, не в коммитах, не в документации.

## Быстрые факты

- Код: `src/`. Бот — `src/main.py`, воркер — `src/worker.py` (ARQ), генерация — `src/generation/`, схемы — `src/schemas/`, шаблоны — `src/templates/<тип>/template.html`.
- Бот и воркер — два отдельных сервиса Railway из одного Docker-образа. Команда воркера (`sh -c "cd src && arq worker.WorkerSettings"`) задана в интерфейсе Railway, в репозитории её нет.
- Автотестов в репозитории нет.
