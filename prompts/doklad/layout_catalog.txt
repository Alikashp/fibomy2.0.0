КАТАЛОГ ТИПОВ СЛАЙДОВ — выбирай layout под смысл контента, а не по порядку.

bullets — 2-4 равнозначных пункта. У КАЖДОГО пункта заполни три поля:
  subtitle — название пункта, 1-3 слова;
  text — одно информационное предложение с конкретным фактом: названием, числом, механизмом;
  icon — имя иконки из списка ниже, подходящее по смыслу.
  НЕ используй, если пункты образуют последовательность (тогда diagram) или сравниваются попарно (тогда two_column).

metrics — 2-4 числа из материала. value — число с единицей ровно как в источнике ("1 240 т", "+5%", "−12%").
  label — к чему число относится (строка и колонка таблицы, 2-5 слов): "рост отгрузок склада Север", а не "рост".
  trend — короткое пояснение из материала или пусто.
  Если в ряду больше 4 элементов (5 складов, 6 классов) или у каждого элемента два числа (доля и рост) — не обрезай ряд:
  покажи все элементы в bullets (по пункту на элемент, с числами) или раздели ряд на два слайда.
  Элемент с падением или невыполнением плана выбрасывать ЗАПРЕЩЕНО.
  Не переводи в проценты то, что в источнике не в процентах.
  Требование или ограничение ("не более 3 дней", "не менее 20 учеников") — это не результат: ставь его только
  с label, где это видно ("предельный срок поставки"), и не ставь на слайд о результатах.
  Нет реальных чисел — НЕ используй этот layout. ЗАПРЕЩЕНО выдумывать числа ради этого layout.

two_column — два параллельных блока по теме слайда. Это может быть:
  • сравнение (до/после, было/стало, в теории/на практике, подход А/подход Б),
  • ИЛИ два самостоятельных тезиса, раскрывающих разные грани одной темы
    (например: «что фиксируем» / «кто отвечает», «внутренние причины» / «внешние причины»).
  Заполни left_title и right_title — название каждого блока по смыслу,
  и до 3 пунктов в left_bullets и right_bullets.
  right_preferred=true — ТОЛЬКО если это сравнение и правая сторона объективно предпочтительнее.
  При двух равнозначных тезисах — false.
  НЕ используй, если содержание не делится на две части естественно — тогда бери bullets.

diagram — процесс, механизм, последовательность шагов (в том числе шаги БЕЗ дат).
  ОБЯЗАТЕЛЬНО mermaid_code, синтаксис graph LR (горизонтально), МАКСИМУМ 6 узлов.
  Подписи узлов 1-3 слова. body_text — 2-3 предложения, поясняющие логику процесса.
  НЕ используй, если связи между элементами нет.

quote — сильный тезис доклада, поданный крупно.
  title — короткая подпись темы. body_text — сам тезис одним предложением.
  subtitle — одно предложение, поясняющее, почему это так.
  ЗАПРЕЩЕНО приписывать тезис реальным людям или книгам — это формулировка самого докладчика.
  Не больше 1 раза за презентацию.

timeline — события с датами. ТОЛЬКО если у КАЖДОГО этапа есть своя дата или период из материала
  ("март", "II полугодие", "2025"); без материала — только общеизвестные исторические даты.
  date — дословно как в источнике, без уточнений. Этапов — столько, сколько в источнике, свои не добавляй.
  Если дат нет или дата одна на все этапы ("весной"), это НЕ timeline: шаги по порядку — diagram, список — bullets.
  Плохо: в материале "Планы на весну: ремонт спортзала, закупка ноутбуков" → "Март: ремонт / Апрель: закупка / Май: подведение итогов".
  Хорошо: bullets с заголовком "Весной — два проекта: спортзал и ноутбуки" и двумя пунктами.

image_full — разбор примера с иллюстрацией. Два сопоставленных блока в two_column-полях
  плюс image_query на английском.

image_hero — когда визуальный образ несёт основную нагрузку.
  ОБЯЗАТЕЛЬНО image_query на английском, title, body_text (2 предложения) и 2 коротких пункта в bullets.

title — только первый слайд. closing — только последний.

ДОПУСТИМЫЕ ИКОНКИ (поле icon, только из этого списка):
file-text, list, check, alert-triangle, clock, calendar, users, user, coin,
chart-bar, target, bulb, search, settings, lock, message-circle, folder,
arrow-up, arrow-right, help-circle, star, bolt, shield, refresh, link

ПРАВИЛА ВЫБОРА:
0. Используй ТОЛЬКО layout из этого каталога. problem, solution, market, competition, team в докладе запрещены.
1. НЕ ставь два слайда с одинаковым layout подряд (слайд выводов перед closing — исключение).
2. НЕ используй один и тот же layout больше 3 раз за презентацию, не считая слайда выводов.
3. Layout определяется формой содержания слайда: числа — metrics, этапы с датами — timeline,
   шаги без дат — diagram, два параллельных блока — two_column. Не выбирай layout ради разнообразия.
4. Выбрал layout — заполни ВСЕ его обязательные поля. Слайд с выбранным layout и пустыми полями — грубая ошибка.
5. Поле title заполняется НА КАЖДОМ слайде и формулирует ВЫВОД слайда — что именно показывают факты, до 10 слов.
   Не копируй заголовки разделов материала и названия шагов структуры.
   Плохо: "Итоги года", "Результаты", "Что сделано", "Выводы", "Общая динамика", пустая строка.
   Хорошо: "Средний балл школы вырос с 4,1 до 4,3", "Склад Север — единственный с падением отгрузок",
   "Подрядчик обязан сдать спортзал до 1 мая".
   Для учебного доклада по теме допустим заголовок-объяснение: "Модель учится, сравнивая ответ с правильным".

ПРИОРИТЕТ ПРАВИЛ: заполняемость важнее разнообразия.
Если для layout нет реального содержания — НЕ выбирай его,
даже если из-за этого разнообразие окажется меньше.
Слайд с выбранным layout и пустыми полями — грубейшая ошибка,
хуже, чем два похожих layout в одной презентации.
